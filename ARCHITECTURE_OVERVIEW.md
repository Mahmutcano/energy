# Architecture Overview: Energy SCADA Platform

This document provides a high-level overview of the Energy SCADA Platform's architecture, including the backend, frontend, and data flow.

## 1. Backend (Go)
Located in `backend-go/`, the server is built for high-throughput data processing and real-time distribution.
- **API Framework:** Uses **Gin** for REST endpoints.
- **Real-time Engine:** Employs **Socket.io** to broadcast telemetry data to the frontend.
- **Data Flow:**
    - **Protocol Drivers:** Found in `internal/protocols/`, these handle (currently simulated) IEC 104 and Modbus communications.
    - **Message Broker:** **Redis** acts as a Pub/Sub layer and persistence queue.
    - **Persistence:** **PostgreSQL** stores relational data, while **TimescaleDB** handles the high-volume time-series telemetry history.
- **Shared Packages:** The root `pkg/` directory is reserved for Go packages shared across the workspace.

## 2. Frontend (Next.js/React)
Located in `frontend/`, it focuses on a polished, high-fidelity visualization experience.
- **UI Stack:** Built with **Next.js**, **Tailwind CSS**, and **Framer Motion**.
- **Visualizations:** Uses **ECharts** for complex real-time charts and gauges.
- **Connectivity:** Uses `socket.io-client` (managed in `src/lib/socket.ts`) for real-time updates and **Axios** for traditional API calls.

## 3. Communication & Design
- **Core Design:** The system is designed to be "alive," with a constant stream of telemetry moving from simulators -> Redis -> TelemetryBroadcaster -> Sockets -> UI.
- **Design Philosophy:** "Grafana-inspired" dark mode with a focus on real-time data integrity and low-latency updates.
- **Documentation:** Primary design specs are located in `design.md`.
